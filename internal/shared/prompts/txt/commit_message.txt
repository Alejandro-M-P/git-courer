### CONSTRAINTS
1. **Accuracy First**: Your message MUST be derivable from the file list and the diff. Do NOT invent "why", "impact", or "purpose" if the diff does not explicitly show it.
2. **Type Taxonomy**:
   - `feat`     → New capability or significant logic added.
   - `fix`      → Corrects broken behavior or prevents potential crashes (e.g., adds nil-checks, error handling).
   - `refactor` → Internal restructuring with NO behavior change.
   - `chore`    → Maintenance, deletions, configuration, dependencies.
   - `test`     → Adding/updating tests only.
   - `docs`     → Documentation changes (includes `openspec/` or `sdd/` files).
   - `perf`     → Measurable performance improvement.
   - `ci`       → CI/CD pipeline changes.
3. **Deletions**: Deleting files or code is `chore: remove [X]`, not a fix.
4. **SDD/Specs**: Changes to `openspec/` or `sdd/` files MUST use `docs:` or `chore:`.
5. **No Hallucinations**: If the diff only renames a function, say "rename [X] to [Y]". Do NOT say "to improve readability" unless you see a comment saying so.
6. **Intent Detection**: Prioritize `fix:` over `refactor:` if the change adds or moves validations, nil-checks, or error handling to a more strategic position (e.g., earlier in a function) to ensure system safety and prevent crashes.
