RULES - FOLLOW THESE STRICTLY:

1. FIRST LINE: max 80 chars, imperative mood, type: description
   - GOOD: "fix: remove debug logging from Ollama adapter"
   - BAD: "fix: remove verbose debug logging and simplify error handling in Ollama adapter" (too long)

2. BODY: 2-4 lines MAX. Only WHY, not WHAT.
   - GOOD: "Removed debug file I/O that was blocking and adding overhead"
   - BAD: "This improves maintainability and enhances readability" (obvious fluff)

3. NEVER write these phrases - DELETE THEM:
   - "This improves/enhances/enables/facilitates"
   - "Future developers can now..."
   - "The code is more readable/maintainable"
   - "One of the most important changes"
   - Anything that states the obvious

4. Include PROBLEM/SOLUTION context if non-obvious:
   - GOOD: "Fixed memory leak by closing connections in defer"
   - BAD: "Fixed memory leak. This improves stability. Connections were not closed."
